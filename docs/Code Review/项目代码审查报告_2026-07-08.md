#### 2.1.2 问题

##### P0 — `_match_condition` 永远返回 False（功能性 Bug）

**文件**：`chuni_eventer_desktop/resource_reference_graph.py:475-500`

```python
def _match_condition(el: "ET.Element", condition: str) -> bool:
    ...
    current = el.getparent() if hasattr(el, "getparent") else el   # ← :494
    while current is not None:
        type_el = current.find(tag_name)
        if type_el is not None and type_el.text:
            return type_el.text.strip() == expected
        current = current.getparent() if hasattr(current, "getparent") else None  # ← :499
    return False
```

**根因**：`el.getparent()` 是 **lxml 的 API**，标准库 `xml.etree.ElementTree.Element` **没有此方法**（已用 `python -c "import xml.etree.ElementTree as ET; el=ET.fromstring('<a/>'); print(hasattr(el,'getparent'))"` 验证返回 `False`）。本模块 `:10` `import xml.etree.ElementTree as ET`，且项目依赖中无 lxml。

**执行路径**：
- `:494` `hasattr(el, "getparent")` → `False` → `current = el`
- 进入 `while`：`current.find(tag_name)` 在 `<trophyName>` 元素上找 `type` 子元素 → 通常 `None`（type 是 trophyName 的叔辈节点，不是子节点）→ 不 return
- `:499` `hasattr(current, "getparent")` → `False` → `current = None`
- `while` 退出 → **返回 `False`**

**影响**：`REF_RULES` 中 9 条带 `condition="type=N"` 的 Reward 规则（`:303-356`，覆盖 ticket/trophy/chara/namePlate/music/mapIcon/systemVoice/avatarAccessory/stage）在 `build_reference_graph:571` 处 `if rule.condition and not _match_condition(...)` 永远 `continue`，**这些引用边全部不被收集**。

后果链：
1. Reward 资源被重映射时，其引用的 trophy/chara/... 的 `FieldEdit` 不产生 → 引用方 XML 仍指向旧 ID → **导入后 ACUS 出现引用断裂**（Reward 指向不存在的资源）。
2. `detect_conflicts` 的悬空引用检测也基于此图，会漏报。
3. 由于 Reward 是「子物质」分发，用户不会立即看到崩溃，而是**在游戏中兑换奖励时才发现无效**，属于隐蔽性高的数据损坏。

**修复建议**：标准库 ElementTree 不支持父指针，需重构。两种方案：

方案 A（推荐，改用 lxml 风格但用 ElementTree 实现）：在 `build_reference_graph` 解析时一次性建立 parent map，把 `RefRule.xpath` 的匹配元素连同其 substance 祖先一起传递：

```python
# 构建时建立 parent 映射
parent_map = {c: p for p in root.iter() for c in p}
# _match_condition 改为接收 parent_map
def _match_condition(el, condition, parent_map):
    current = parent_map.get(el)
    while current is not None:
        type_el = current.find(tag_name)
        if type_el is not None and type_el.text and type_el.text.strip() == expected:
            return True
        current = parent_map.get(current)
    return False
```

方案 B：Reward 规则改用带条件的 xpath（如 `.//RewardSubstanceData[type/text()="2"]/trophy/trophyName/id`），让 `findall` 直接筛选，绕过 `_match_condition`。

**建议补充回归测试**：构造一个含 `type=2` trophy 子物质的 Reward.xml，断言 `build_reference_graph` 产生指向 trophy 的 RefEdge。

##### P1 — `_STRATEGIES` 类型注解用小写 `callable`

**文件**：`chuni_eventer_desktop/resource_id_allocator.py:276`

```python
_STRATEGIES: dict[str, callable] = {
```

小写 `callable` 是内建**函数**，不是类型。正确写法应为 `Callable[..., Any]`（`from typing import Callable`）或 `dict[str, Callable[[Path, int, dict], int | tuple[int, ...]]]`。

运行时不报错（注解默认不求值，且 `from __future__ import annotations` 使其全为字符串），但 mypy/pyright 会告警，IDE 跳转失效。属低危但应修正。

##### P1 — `field_wall_from_image` 临时文件清理逻辑失效

**文件**：`chuni_eventer_desktop/field_wall_from_image.py:116-117`

```python
finally:
    if 'norm_tmp' in dir():
        norm_tmp.unlink(missing_ok=True)
```

`dir()` 不带参数时返回**当前作用域的名字列表**，但局部变量名是否出现在 `dir()` 中取决于实现（CPython 中 `dir()` 在函数内通常返回模块级名字，不含局部变量）。更可靠写法：

```python
finally:
    if 'norm_tmp' in locals():
        norm_tmp.unlink(missing_ok=True)
```

或更清晰地：初始化 `norm_tmp: Path | None = None`，`finally` 中 `if norm_tmp is not None: norm_tmp.unlink(missing_ok=True)`。

**影响**：若 `ingest_to_bc3_dds` 抛异常，`norm_tmp` 临时 PNG 可能残留（在系统 temp 目录）。

##### P2 — `resource_pack_import.scan_package_resources` 重复扫描逻辑

**文件**：`chuni_eventer_desktop/resource_pack_import.py:151-216`

`scan_dispatch` 循环（`:151-174`）已扫描 11 类资源，随后 `:178-216` 又 `rglob("*.xml")` 递归扫描并用 `any(...)` 判断是否已覆盖。这段「补漏扫描」逻辑：

1. `:185-191` 的 `any(r.xml_path == rel and r.kind in (...) for r in resources)` 是 O(n) 查重，对大包性能差（应先建 `set` 索引）。
2. `:215` `except Exception: continue` 静默吞 XML 解析错误，与 `import_resource_pack:892-903` 的显式 XML 校验**重复且矛盾**（前者静默跳过坏 XML，后者又把坏 XML 当致命错误）。

**建议**：补漏扫描的 `except` 至少 `logging.debug` 记录；查重用 `seen` 集合替代 `any()`。

##### P2 — `resource_id_allocator._scan_directory_numeric_names` 数字解析逻辑冗余

**文件**：`chuni_eventer_desktop/resource_id_allocator.py:96-103`

```python
if suffix.isdigit() or (suffix and suffix.lstrip("0").isdigit() and int(suffix) > 0):
```

`suffix.isdigit()` 已覆盖纯数字（含 `"007"`），后半句 `suffix.lstrip("0").isdigit() and int(suffix) > 0` 实际上只多覆盖了 `suffix` 含前导零但 `isdigit()` 本就为真的情况——逻辑冗余。且 `int(suffix) > 0` 排除了 ID=0 的合法情况。建议简化为 `if suffix.isdigit(): ids.add(int(suffix))`。

新增的 `resource_pack_import.py`、`resource_reference_graph.py`、`resource_xml_rewriter.py` 贡献了大量裸 `ET.parse`，且这些 XML 来自**用户提供的压缩包**（外部输入），XXE 风险面比上轮（仅本地 ACUS）更高。

**建议**：优先为资源导入链路引入 `safe_parse()`：

```python
def safe_parse(path: Path) -> ET.ElementTree:
    parser = ET.XMLParser(resolve_entities=False)
    return ET.parse(str(path), parser=parser)
```

并在 `resource_reference_graph.py`、`resource_pack_import.py`、`resource_xml_rewriter.py` 全部替换。

## 6. 结论

v0.7.9 → v0.8.0 是一个**功能密集、架构有亮点**的迭代：资源压缩包快捷导入的声明式引用图设计、启动性能优化、配置原子写入落地，都体现了工程能力的提升，且对上轮审查形成了良好的修复闭环。

整体而言，项目的工程质量在持续向好，主要短板仍是**测试基础设施缺失**与**异常可见性不足**两项，这两项的改善将显著放大已有架构设计的价值。
