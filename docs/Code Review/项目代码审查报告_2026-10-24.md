# 项目代码审查报告（2026-10-24）

> **范围**：整个工作区（`HEAD` = 91e267b + 未提交改动）
> **版本**：v0.8.3
> **方式**：只读静态审查（未运行程序、未做运行时验证）
> **本次重点**：UI 里不同页面之间会不会「相互卡死」

---

## 1. 结论先行

**会。** 但机制不是经典的死锁（互等锁那一类），而是：**整个应用只有一个 GUI 线程，而多处代码在这个线程上同步 `wait()` 后台线程**。一页在等，全部页面一起停摆，Windows 会直接把标题栏改成「未响应」。

三条最现实的触发路径：

| # | 路径 | 上限 |
|---|------|------|
| 1 | 下载/转换类弹窗进行中，点「关闭 / × / Esc / 取消」→ `closeEvent`/`reject` 在主线程 `await_qthreads()` | **300 秒** |
| 2 | 歌曲卡片页封面线程在跑时滚动、切分类或刷新 → `_stop_jacket_loader()` 主线程等待 | **60 秒** |
| 3 | 伴侣弹窗点「刷新在线模型」→ 网络请求直接跑在 GUI 线程 | **20 秒+** |

另外还有两类「看起来也像卡死、但性质不同」的问题：

- **切页同步扫盘**：每次切分类都会在 GUI 线程重新解析全部 XML，数据量大时表现为「点了没反应」；
- **ApplicationModal 弹窗**：会把整个应用（含所有页面）锁死，直到弹窗关闭。

## 3. P0（确凿的功能性卡死 / 崩溃）

### P0-1 关闭后台任务弹窗会冻结整个应用（最长 300 秒）

**证据**：`qthread_lifecycle.py:7` 定义 `DEFAULT_QTHREAD_JOIN_MS = 300_000`，`await_qthreads()`（`:20-23`）直接在调用者线程上 `th.wait(timeout_ms)`。而这个函数的调用点几乎全在 GUI 线程的关闭/取消路径上：

| 调用点 | 触发动作 | 等待的线程 |
|--------|----------|------------|
| `ui/pjsk_hub_dialog.py:392-398` | 关闭 / Esc | 转换线程（含网络与文件转换） |
| `ui/swan_sheet_download_dialog.py:193-202` | 关闭 / Esc | 列表拉取 + 下载 + 解压，3 个 |
| `ui/pjsk_sus_download_dialog.py:298-307` | 关闭 / Esc | 谱面加载 + 缓存，2 个 |
| `ui/pgko_sheet_download_dialog.py:798-813` | 关闭 / Esc | 拉取 + 下载 + 转换 + UGC，4 个 |
| `ui/resource_pack_settings_panel.py:640-642` | 点「取消」 | 计划 + 应用，2 个 |
| `ui/system_voice_page.py:309-311` | 页面被隐藏（关打包向导） | 打包线程 |

**为什么一定会卡**：这些 worker 里没有取消令牌（`threading.Event`），`th.wait()` 不会让任务提前结束；网络 `urlopen` 的超时是 20–300 秒（`pjsk_sheet_client.py:84-108`、`psb_action_dialog.py:97,111`）。用户在网络慢的时候点关闭，主线程就一直等到任务自然结束——期间主窗口所有页面都不刷新、不响应。

**修法**：
1. worker 增加 `threading.Event` 取消位，长循环与下载分块处检查；
2. 关闭路径**不再 `wait()`**：置取消位 → `dialog.hide()` → `thread.finished.connect(dialog.deleteLater)`，让线程跑完自己退场；
3. 确需等待时上限压到 100ms 级，并把 QThread 的 owner 挂到 `QApplication.instance()`，避免父窗销毁带走运行中的线程。

### P0-2 未提交代码：「新增 → 伙伴」抛 AttributeError

**证据**：`ui/main_window.py:1120` 新增了 `game_root=self._game_root`，但 `MainWindow` 上**没有** `_game_root` 这个属性（只有 `_GameIndexWorker` 里有，`:98`）。配置项在 `self._cfg.game_root`。`_on_add` 的 `try` 只包住了 `:812-827` 的前置检查，这个分支在 `:1116`，异常会直接逃逸出槽函数。

**影响**：PyQt6 对槽函数里逃逸的异常会走 `qFatal` 路径（`app.py:111-118` 的 `excepthook` 只记录不拦截），轻则入口无反应，重则进程终止。

**修法**：改为 `game_root=self._cfg.game_root or None`（`PsbActionDialog` 内部用 `Path(game_root) if game_root else None`，传字符串也可）。

### P0-3 伴侣弹窗「刷新在线模型」在 GUI 线程发网络请求

**证据**：`ui/psb_action_dialog.py:815` 把刷新按钮直连 `_fetch_models`；`:1212-1218` 里同步调用 `_LolicountClient().list_models()`，内部 `urlopen(..., timeout=20)`（`:97`）。

**影响**：点一下按钮，整个应用最长 20 秒+ 无响应；网络不通时更久（DNS 超时叠加）。这与同文件里其它任务都用 `_TaskWorker` 后台执行的做法自相矛盾。

**修法**：改用现成的 `_TaskWorker`，按钮置灰 + 状态文案，失败走 `fly_critical`。

## 4. P1（真实卡顿 / 放大卡死窗口）

### P1-1 歌曲卡片页：封面线程同步等待 60 秒

`ui/music_cards_view.py:537-544` 的 `_stop_jacket_loader()` 先 `quit()` 再 `await_qthreads(thread, timeout_ms=60_000)`。但 `_JacketLoadWorker.run()`（`:462-475`）是阻塞循环，`quit()` 不会打断它，只能靠 generation 在下一次循环边界退出（`:465`）。因此等待时长取决于**当前那一张 DDS 的转码耗时**；如果外部转码器卡住，就是整 60 秒。`set_items()`（`:663-664`）、`_schedule_jacket_loads()`（`:603`）都会走到这里——也就是**切分类、刷新、滚动**都可能触发。

**修法**：把 `await_qthreads` 换成「不等待、断引用、靠 generation 丢弃 + finished 自动 deleteLater」，或上限压到 50ms。

### P1-2 每次切分类都在 GUI 线程全量重扫 XML

`ui/manager_widget.py:308-319` `set_kind()` → `reload()`（`:354`），`:392-513` 直接调用 `scan_quests/scan_events/scan_music/...`；`acus_scan.py:332-393` 对每个 `Music.xml` 做 `ET.parse`，**没有任何缓存**。事件/乐曲数量上千时，切一次分类就是几百毫秒到数秒的整窗冻结。

**修法**：按 `(kind, acus_root, mtime)` 缓存扫描结果；首次扫描放 worker + 进度条；或至少给个 `QApplication.setOverrideCursor` 让用户知道在干活。

### P1-3 游戏索引 JSON 每次调用都全量解析

`ui/main_window.py:448-452` 的 `_resolve_game_index()` 每次 `load_cached_game_index()`；`game_data_index.py:907-920` 每次 `json.loads` + `from_json`，无内存缓存。它被 `:784/891/972/994/1005/1031/1080` 以及多个弹窗反复调用——每开一次「音乐选择器 / 游戏资源浏览」都要重读解析一遍索引文件。

**修法**：模块级按 `(path, mtime, size)` 记忆化；索引被重建时主动失效。

### P1-4 两个 ApplicationModal 弹窗会锁死整个应用

`ui/trophy_texture_compose_dialog.py:81-82`、`ui/trophy_pjsk_generator_dialog.py:202-203` 显式设了 `ApplicationModal`。这与全项目其它弹窗的 `WindowModal` 约定不一致，弹窗打开期间主窗口任何页面都点不动。

**修法**：确认是否必须跨窗口；否则改回 `WindowModal`。

### P1-5 关程序时 2.5 秒后 `terminate()`，且只登记了 2 个线程

`qthread_lifecycle.py:26-38` 的 `shutdown_qthreads_for_exit()` 超时后直接 `terminate()`；`main_window.py:173-185` 只登记了索引线程和工具引导线程。封面线程（`music_cards_view.py:606` 的 parent 是 view）、关于页检查更新线程（`settings_about_panel.py:217`）、资源包线程（`resource_pack_settings_panel.py:498/577`）都没纳入。

**影响**：`terminate()` 可能把正在进行 XML/索引写盘的线程打断，留下半写文件；未登记的线程在窗口销毁时会报 `QThread: Destroyed while thread is still running`。

**修法**：建一个进程级线程登记表，`MainWindow.closeEvent` 统一收尾；`terminate()` 只作为最后兜底并记录日志。

### P1-6 `ThreadPoolExecutor` 的「3 秒回退」是假的

`external_tools.py:600-628`：`with ThreadPoolExecutor(max_workers=1) as executor:` 里 `future.result(timeout=3.0)`，超时后 `return`。但退出 `with` 会执行 `shutdown(wait=True)`，而 `_do_github_query` 里的 `fetch_github_release_latest` 超时是 12 秒（`github_release.py:64,75`）。所以「3 秒后回退」实际会**阻塞到 12 秒**。它跑在 worker 线程上，又会被 P0-1 的 300 秒 `wait()` 放大。

**修法**：显式 `executor.shutdown(wait=False)`，或用 `daemon` 线程 + 放弃结果。

### P1-7 DDS 批量编码：嵌套事件循环 + `wait(120s)`

`ui/dds_progress.py:71-99`：在已经是模态的调用链里再开一个 `QEventLoop`，结束后 `thread.wait(120_000)`。`loop.quit()` 只由 `thread.finished` 触发，一旦弹窗被外部销毁或事件循环被打断，就落到 120 秒的 `wait()` 上；同时 `QApplication.processEvents()`（`:96`）会带来重入。

**修法**：统一成项目里已经在用的非阻塞 `QProgressDialog` + 信号回主线程模式，去掉 `QEventLoop` 和 `wait()`。

## 6. Standards（规范与坏味道轴）

本仓库没有 `CODING_STANDARDS.md`，以下以「仓库既有惯例 + 文档化口径 + 坏味道基线」为准。

**硬违规 / 明显缺陷**

1. `ui/main_window.py:1120` 使用了不存在的 `self._game_root` —— 未提交改动里的确定性 Bug（见 P0-2）。
2. 5 个弹窗各自复制了一份同形的 `_await_bg_threads()`（`swan:193`、`pjsk_sus:298`、`pgko:798`、`pjsk_hub:392`、`resource_pack:640`）——**Duplicated Code**。应抽成一个 `BackgroundTaskGroup`（登记线程 + 取消位 + 统一收尾），五处共用。
3. `qthread_lifecycle.py` 里的 `300_000` / `60_000` / `2_500` 是散落的魔法数——**Primitive Obsession / Mysterious Name**：调用点写 `await_qthreads(th)` 完全看不出会阻塞五分钟。

**判断项**

4. `fluent_dialogs.py` 里的 `_release_qt_input_grabs`、`_ensure_enabled_for_dialog_parent`、`_run_modal_with_enabled_top` 是对「整窗点不动」的逐点打补丁——**Shotgun Surgery** 的前兆：同类问题在多个弹窗里以不同形式复发，说明缺少一个统一的「忙碌/模态状态机」。
5. `map_add_dialog.py` 4494 行仍是上帝模块（**Divergent Change**）。
6. 正面例子：`mate_layout.py` 把坐标换算抽成无 Qt 依赖的纯函数 + `dataclass`，并配了 `scripts/test_mate_layout.py`。这类模块应当作为后续拆分的模板。

## 9. 结论

「页面之间相互卡死」的根因不在页面本身，而在于**页面/弹窗把后台线程的生命周期管理做成了主线程阻塞等待**。目前至少有 6 个弹窗的关闭路径、1 个卡片视图的刷新路径会把整个应用按在 60–300 秒的停顿里；再加 3 处 GUI 线程上的网络/全量扫描。只要按「取消位 + 不等待 + 后台化」三条原则收敛，这类问题可以系统性消除，而不是继续在 `fluent_dialogs.py` 里加补丁。
