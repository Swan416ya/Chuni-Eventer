## 0. 执行摘要（TL;DR）

Chuni-Eventer 是一个**功能丰富、工程化程度相当高**的 PyQt6 桌面工具，面向 CHUNITHM 自制内容（ACUS）维护，覆盖谱面转换、角色/地图/活动/称号生成、DDS/AFB/ACB 资源处理、多谱源下载（pgko/swan/pjsk/github）等完整链路。整体架构清晰、文档详尽（40+ 篇专题文档）、打包流程规范、安全实践基本到位（subprocess 无 shell=True、网络使用 `ssl.create_default_context()`）。

但项目存在若干**结构性技术债**，按优先级排序：

| 优先级 | 问题 | 影响 |

| **P1（质量）** | 341 处 `except Exception` 静默吞异常；无任何测试用例 | 可维护性、可调试性 |

| **P2（工程）** | 依赖未锁版本；配置无原子写入；版本号硬编码 | 可复现性、数据安全 |

## 1. 项目概览

### 1.1 定位

`Chuni-Eventer` 是一个 Windows 本地桌面工具，用于维护 CHUNITHM 相关的 **ACUS 资源目录**（All Net Custom User Space）。用户在工具内创建/编辑自制角色、地图、活动、称号、奖励，导入谱面（SUS / mgxc / ugc），最终将编辑好的 `ACUS` 作为一个 opt 放入游戏。

### 1.2 技术栈

| 层 | 技术 |
|----|------|
| GUI | PyQt6 6.10+ + PyQt6-Fluent-Widgets 1.7+（Material/Fluent 风格） |
| 图像 | Pillow 12+（DDS/封面/Jacket） |
| DDS 编解码 | quicktex 0.3+（BC3/DXT5，子进程隔离运行） |
| 音频 | PyCriCodecsEx 0.0.5+（CRI MH HCA）、ffmpeg（外部） |
| 档案 | py7zr 0.20+（7z 谱面包） |
| 谱面转换 | PenguinTools.CLI（C# 子模块，外部 subprocess） |
| 打包 | PyInstaller 6.3+，单文件 exe |

### 1.3 启动流程（`chuni_eventer_desktop/app.py:139-184` → `main()`）

1. 启动性能埋点 `startup_mark("app.main:enter")`
2. PyInstaller DLL 路径修正（`frozen_runtime.py`，仅 `sys.frozen`）
3. Windows `AppUserModelID` 设置（任务栏归属）
4. 崩溃日志：`sys.excepthook` + `unraisablehook` + `faulthandler` → `<cache>/logs/`
5. QApplication 创建 + QFluentWidgets 主题
6. MainWindow 创建（延迟导入）
7. `QTimer.singleShot(0, _finish_startup)` 异步完成 UI 构建
8. 启动埋点汇总（`CHUNI_STARTUP_PROFILE=1` 时打印 Top-15 慢项）

**启动优化做得相当扎实**：有专门的 `docs/性能优化/` 4 篇文档、`startup_profile.py` 埋点、分类懒加载方案。这部分是项目的亮点。

### 2.2 架构评价

**优点**：
- 模块按职责划分清晰，文件命名规范（`<对象>_<动作>.py`），易于定位。
- UI 与业务逻辑分离较好，业务模块基本不依赖 Qt。
- 后台任务统一用 `QThread + QObject worker` 模式（`qthread_lifecycle.py` 统一管理生命周期），避免了 Qt 线程常见坑。
- 谱面转换核心逻辑已收敛到 `_suspect/` 子包（从 Soyandroid/suspect 派生），主流程通过 `pgko_to_c2s.py` 编排。

**问题**：
- `chuni_eventer_desktop/` 根下平铺 58 个 `.py`，**缺少子包分层**。建议按上文归类拆为 `core/`、`convert/`、`assets/`、`net/`、`xml/` 等子包，降低认知负担。
- `_suspect/` 目录名暗示"实验/可疑代码"，却被主流程直接引用（`pgko_to_c2s.py:32` 从 `._suspect.c2s_emit` 导入 20 个类）。命名与实际地位不符，易误导维护者。

## 3. 代码质量审查

### 3.1 P0 — 确凿 Bug

#### 3.1.1 `convert_pgko_audio_to_chuni_from_pick` 引用未定义变量

**文件**：`chuni_eventer_desktop/pgko_to_c2s.py:2069-2124`

```python
def convert_pgko_audio_to_chuni_from_pick(
    pick: PgkoChartPick, *, music_id_override: int | None = None
) -> dict[str, object]:
    ...
    return {
        "musicId": music_id,
        "audioSource": str(src_audio),   # ← 第 2117 行：src_audio 从未定义
        "cueDirectory": _rel(cue_dir),
        ...
    }
```

函数体内可用变量为 `prep.safe_bgm_wav`，但返回字典引用了不存在的 `src_audio`。**一旦调用此函数必抛 `NameError`**。该函数被 `ui/pgko_sheet_download_dialog.py:49` 导入（虽然 grep 未见显式调用点，但导入即表明设计意图为使用）。

**修复建议**：确认 `audioSource` 字段应指向 `prep.safe_bgm_wav` 还是 `prep.cli_mgxc`，替换 `src_audio`。

### 3.2 P1 — 异常处理

#### 3.2.1 341 处 `except Exception` 静默吞异常

全项目共 **341 处** `except Exception`，其中大量为 `continue` / `return None` / `pass`，完全吞掉堆栈，无任何日志。典型案例：

| 文件 | 行号 | 模式 |
|------|------|------|
| `acus_scan.py` | 248/266/282/299/317/381/396/425/449/485/501/518/562/593/611/631/769 等 | XML 解析循环 `except Exception: continue` — 解析器崩溃时静默跳过整条记录，用户无从知晓扫描结果不完整 |
| `pgko_to_c2s.py` | 231/237/242/247/432/527/1048-1092 等 | UGC 字段解析失败 `pass` — 可能导致谱面数据静默错误 |
| `pgko_to_c2s.py:2301` | `_write_pgko_jacket_dds` 中 `except Exception: pass` | 静默跳过封面生成失败 |
| `ui/fluent_dialogs.py` | 42/143/145/177/197/265 等 50+ 行 | UI 层吞异常，用户报错信息缺失上下文 |

**影响**：故障不可见 = 不可调试。当用户反馈"扫描结果少了条目"或"谱面音不准"时，开发者无任何线索。

**建议**：
- 关键路径（扫描、转换、安装）至少 `logging.warning("...: %s", e, exc_info=True)`。
- 网络请求、文件 I/O 用具体异常类型（`URLError`/`OSError`/`json.JSONDecodeError`）。
- 引入统一日志框架（项目已用 `logging`？实际多为 `print`，见 3.2.2）。

#### 3.2.2 40 处 `print` 调试残留

| 文件 | 行号 | 内容 |
|------|------|------|
| `ui/manager_widget.py` | 1082-1166 | 大量 `[stage-debug]` print，含 `QTimer.singleShot` 延迟调试 |
| `ui/trophy_add_dialog.py` | 449-468 | `[trophy-debug]` print |
| `ui/trophy_texture_compose_dialog.py` | 133 | print |
| `ui/trophy_pjsk_generator_dialog.py` | 312 | print |
| `quicktex_worker.py` | 20/31/43 | print/stderr |
| `repack_system_voice_acb.py` | 155 | print |
| `startup_profile.py` | 39/55/57/61 | profile print（可接受但应走 logging） |

**建议**：统一替换为 `logging.getLogger(__name__)`，通过环境变量控制级别。

### 3.4 P2 — 工程实践

#### 3.4.1 依赖未锁版本

`requirements.txt` 全部用 `>=` 无上限，无 lock file：

```
PyQt6>=6.10.0
PyQt6-Fluent-Widgets>=1.7.0
Pillow>=12.0.0
quicktex>=0.3.0
PyCriCodecsEx>=0.0.5
py7zr>=0.20.0
```

不同时间安装可能获得不同大版本。`quicktex`、`PyCriCodecsEx` 仅限 Windows 但无平台约束。**建议**：生成 `requirements.lock`（`pip freeze`）或迁移到 `pyproject.toml` + 锁文件。

#### 3.4.2 配置无原子写入

所有 `Path.write_text()` / `Path.write_bytes()` 直接覆盖，无"写 `.tmp` → `os.replace`"模式：

- `acus_workspace.py:317` — `AcusConfig.save()` 直接覆盖 `.config.json`，进程崩溃则配置损坏。
- `game_data_index.py:914` — `save_game_data_index` 直接覆盖。

**建议**：关键配置用 `tempfile.NamedTemporaryFile` + `os.replace` 原子写入。

#### 3.4.3 版本号硬编码且与发布说明分离

`version.py:3` 硬编码 `APP_VERSION = "0.7.9"`；发布说明在 `packaging/GITHUB_RELEASE_v0.X.Y.md`（18 个文件，v0.1.0 → v0.7.9）。代码版本与 release note 手动同步，易漂移。**建议**：从单一来源（如 git tag 或 `pyproject.toml`）派生版本号。

#### 3.4.4 硬编码上游版本

`external_tools.py:115` `MUA_RELEASE_TAG = "v0.7.1"`、第 90 行 `_PENGUIN_TOOLS_CLI_FALLBACK_TAG = "v1.12.1"`、`game_data_index.py:78` `INDEX_VERSION = 4`。上游更新需改源码重打包。

### 4.2 网络请求 — 证书验证正确 ✅

全部网络客户端使用 `ssl.create_default_context()`（13 处），**未发现 `_create_unverified_context()` 绕过**：

`backend_upload_client.py`、`external_tools.py`、`github_release.py`、`pgko_sheet_client.py`、`pjsk_sheet_client.py`、`swan_sheet_client.py` 均正确。

### 4.3 路径处理 — 基本安全 ⚠️

路径拼接均用 `Path` 对象，无明显注入。但 `pgko_to_c2s.py:1366-1390` `_resolve_audio_path_in_dir` 接受用户输入路径，`base / filename` 若 `filename` 含 `..` 可逃逸基目录——虽有后续 `p.relative_to(base)` 校验，但中间 `p.is_file()` 可能在穿越期间读取意外文件。**建议**：先 `relative_to` 校验再 `is_file()`。

### 4.4 XML 解析 — XXE 风险低 ⚠️

约 90 处 `ET.parse()` 未设 `resolve_entities=False`。因解析的是本地 ACUS 文件（非网络输入），实际风险低；但若用户放置恶意 XML 仍有 XXE 可能。**建议**：封装统一 `safe_parse()` 使用 `ET.XMLParser(resolve_entities=False)`。

## 5. 测试与可维护性

### 5.1 测试覆盖 — 零 ❌

- **无 `tests/` 目录，无任何 Python 测试文件**。
- `test_out/` 为空目录。
- `_selfcontained_test.c2s`（156KB）为手动测试谱面，非自动化测试。

对于一个有 4.5 万行、含复杂二进制格式解析（mgxc/DDS/AFB/ACB）和谐面转换逻辑的项目，**零测试是最大的可维护性风险**。谱面转换（`convert_pgko_chart_pick_to_c2s`、`install_pgko_pick_to_acus`）任何改动都无回归保护。

**建议**：至少为核心转换函数编写快照测试（给定 mgxc 输入 → 期望 c2s 输出），并覆盖 ID 段分配、XML 写入逻辑。

### 5.2 文档 — 优秀 ✅

`docs/` 含 40+ 篇专题文档，按 9 个主题分类（界面与工作区、谱面转换与格式、UGC与桥接、活动与玩法机制、角色与元数据、接口与依赖、资源与打包、性能优化、Introduction）。有 `docs/README.md` 索引。文档质量是项目的显著亮点。

**小问题**：`docs/README.md:14-15` 存在重复条目（同一文件链接出现两次）。

## 6. 打包与发布

### 6.1 PyInstaller 打包 — 规范 ✅

- 主 spec：`ChuniEventer.spec`（单文件 exe，`console=False`，入口 `run_desktop.py`）
- 资源打包：`static/`（图标/字体/工具）、`data/`（种子 XML/模板 ACB/AFB）、`assets/icon.ico`
- 依赖收集：`collect_all()` 拉取 qfluentwidgets/qframelesswindow/quicktex/PIL/PyCriCodecsEx
- 体积优化：`packaging/pyinstaller_filters.py` 两阶段过滤（排除 30+ 未用 PyQt6 模块）
- 有专门的 `docs/资源与打包/` 4 篇体积分析文档

### 6.2 quicktex 子进程隔离 — 巧妙 ✅

`quicktex_worker.py` + `cli_flags.py`(`--chuni-quicktex-worker`) 实现 quicktex 编码子进程隔离，避免 Windows 上 quicktex 原生库偶发 access violation 导致父进程崩溃。这是良好的健壮性设计。

### 6.3 仓库卫生

`.gitignore` 规范（排除 `ACUS/`、`A001/`、`pjsk_cache/`、`build/`、`dist/`、`PenguinTools/` 等）。但 `docs/Introduction/` 含未压缩 MP4/MKV（46MB+）直接提交仓库——已通过 `.gitignore` 排除，但历史可能已入库。**建议**：考虑 Git LFS 或从历史清理。
